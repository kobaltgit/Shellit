# Банк идей и бэклог Shellit (Feature Ideas & Backlog)

В данном файле фиксируются и приоритизируются все идеи развития Shellit.

### Грейды приоритетов:

- **P0 (Critical / Quick Wins):** Ключевой UX, защита данных или простые задачи (S) с мгновенным профитом. В разработке в первую очередь.
- **P1 (High Value):** Крупные киллер-фичи (M/L), дающие сильное конкурентное преимущество.
- **P2 (Enterprise & Niche):** Масштабные (XL) или специализированные модули, требующие отдельной инфраструктуры.
- **Deferred:** Отложено до версий после 1.0+.
- **Implemented:** Готово и внедрено в кодовую базу.

## 3. Детальные спецификации комплексных задач (P0–P2)

<details open>
<summary><b>Развернуть спецификацию IDEA-029: Core Security Hardening & Zero-Trust Architecture (P0 — Critical)</b></summary>

1. **Защита от Man-in-the-Middle (SSH TOFU & Known Hosts):**
   - **Таблица `known_hosts` в `storage_vault`:** поля `host`, `port`, `key_type` (ed25519, ecdsa, rsa), `fingerprint_sha256`, `first_seen_at`, `last_seen_at`.
   - **Интеграция в `ssh_network_core`:** подключение асинхронного обработчика `onVerifyHostKey` в `SSHClient` (`dartssh2`). Автоматическая проверка полученного ключа хоста по локальной зашифрованной базе `known_hosts`.
   - **Диалог Trust-On-First-Use (TOFU):** при первом подключении всплывает модальное окно верификации с отпечатком `SHA256:<base64>` и визуальным ASCII Randomart (в стиле OpenSSH) с кнопками «Отмена» и «Доверять и сохранить».
   - **Блокировка подмены ключа (MitM Alert):** при несовпадении сохранённого отпечатка соединение немедленно аварийно разрывается с генерацией критического предупреждения: *«WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED! Возможен перехват сессии.»* с блокировкой до осознанного ручного сброса ключа пользователем.

2. **Криптографическая строгость и честный Zero-Knowledge Vault:**
   - **Гарантированное зануление памяти:** вызов метода `destroy()` у объектов `SecretKey` (`package:cryptography`) при блокировке хранилища или сбросе контекста; очистка временных байтовых буферов через `zeroize()`.
   - **Автоблокировка сейфа (Auto-Lock):** настраиваемый таймаут неактивности (5 / 15 / 30 минут) и авто-блокировка при сворачивании приложения со стиранием мастер-ключа из оперативной памяти `VaultSecurityContext`.
   - **Криптографические тесты (RFC/NIST Vectors):** интеграция в тестовый сьют `storage_vault_test.dart` официальных тестовых векторов RFC 9106 для Argon2id и NIST KAT для AES-256-GCM.
   - **Честное информирование:** указание реального статуса архитектуры безопасности и используемых стандартов в диалоге «О программе» без необоснованного маркетингового пафоса.

3. **Zero-Trust песочница плагинов (Plugin SDK Hardening):**
   - **Явное согласие пользователя (Consent Prompt):** при импорте архива `.shellit` отображается модальное окно со списком запрашиваемых манифестом разрешений (`terminal:execute`, `vault:read_hosts`, `clipboard:read`) с требованием явного подтверждения установки пользователем.
   - **Строгий Content Security Policy (CSP):** локальный сервер плагинов `PluginStaticServer` принудительно отдаёт заголовки `Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline'; connect-src 'none';`, запрещая несанкционированные исходящие сетевые запросы из WebView2.
   - **Индикация выполнения:** визуальный бейдж над терминалом при выполнении команд, инициированных сторонними плагинами через JSON-RPC мост.
   - **Изоляция локального хранилища:** жесткое ограничение прав `storageLocal` рамками директории `plugins/<plugin_id>/storage.json` без доступа к файловой системе хоста.

4. **Инженерная защита Production (Prod Guard Evolution):**
   - **Read-Only SSH сессии:** опция подключения к хосту в режиме «Только чтение» (полное программное отключение пересылки клавиатурного ввода в PTY-канал; сессия доступна строго для мониторинга, инспекции логов `tail -f` и `htop` без физической возможности выполнить деструктивную команду).
   - **Multi-line Paste Protection:** при вставке многострочного скрипта на серверах со статусом `PRODUCTION` всплывает модальное окно подтверждения с подсветкой синтаксиса и очисткой хвостовых переводов строк.
   - **Ручное подтверждение имени хоста:** для команд наивысшего риска (`rm -rf /`, `mkfs`, `drop database`, `reboot`) требование ввести имя хоста с клавиатуры (паттерн безопасности GitHub).
   - **Позиционирование:** открытое обозначение эвристического regex-чекера как «UX-фильтра от случайных опечаток», а не абсолютного барьера безопасности.

5. **Гигиена нативных зависимостей:**
   - **Архитектурное разграничение:** фиксация того, что удаленные SSH/SFTP соединения работают на 100% чистом Dart без привлечения стороннего нативного C-кода.
   - **Изоляция Local PTY:** ограничение области применения пакета `flutter_pty2` исключительно локальным терминалом машины разработчика с регулярным аудитом апстрим-репозитория.
</details>

<summary><b>Развернуть спецификацию IDEA-027: Native Dual-Pane SFTP Pro Suite (P0)</b></summary>

1. **Рекурсивная передача и пакетные очереди:** скачивание и заливка каталогов с сохранением дерева папок; потоковое создание вложенных директорий.

5. **Клавиатурная эргономика:** стрелки навигации, `Enter` (вход), `Backspace` / `Alt+Up` (наверх), `F2` (имя), `Delete` (удаление), `F5`/`F6` (копирование/перемещение).
6. **Встроенный редактор & Quick Look:** быстрый предпросмотр конфигов по `Space`, редактирование с подсветкой синтаксиса и сохранением на сервер по `Ctrl+S`.
7. **Очередь и докачка:** возобновление передачи через байтовое смещение (`offset`), ограничение параллельных потоков (2-3), расчет ETA и скорости.
8. **Навигация:** хлебные крошки, история (`<` / `>`), живой фильтр в папке, закладки (`~`, `/var/www`, `/etc`), обработка symlink.
9. **Серверные операции:** архивация/распаковка (`tar.gz`/`zip` через SSH exec), рекурсивный `chmod -R`, инфо о диске (`df -h`).
</details>

<details>
<summary><b>Развернуть спецификацию IDEA-022: Zero-Config DB & Redis Explorer (P1)</b></summary>

1. **Zero-Config SSH Tunneling:** прозрачный авто-проброс портов через сессию хоста.
2. **Поддерживаемые СУБД (чистый Dart):**
   - PostgreSQL (`postgres`): схема, Data Grid, пагинация, SQL Scratchpad, мониторинг `pg_stat_activity`.

   - SQLite (`sqlite3`): открытие `.db` файлов в 2 клика прямо из SFTP.
   - MySQL / MariaDB (`mysql_client`): таблицы и фильтры.
3. **PROD Guard:** принудительный Read-Only на продакшене, перехват `UPDATE / DELETE / DROP` с транзакционным подтверждением.

<details>
<summary><b>Развернуть спецификацию IDEA-026: Multi-Vault Profiles & Team Collaboration (P2)</b></summary>

1. **Изолированные профили-сейфы:** раздельные базы `~/.shellit/vaults/{id}.vault.db` (Personal / Work / Project).
2. **On-Premise Sync (`servers/sync_server`):** командная синхронизация без публичных облаков, ролевая модель (Owner, DevOps, Developer, Junior) и политика скрытых ключей (Connect-Only без права экспорта).

5. **Multiplayer Debugging:** шаринг сессии терминала для совместного расследования аварий на одном экране.
</details>

3. **Механика интеграции с бэкендом сайта (`shellit.top`):**
   - Отправка прямого HTTP POST-запроса через `http` клиент Dart:
     - URL: `https://shellit.top/api/collections/feedback_reports/records`
     - Header: `Content-Type: application/json`
     - JSON Payload:

     - Авто-определение ОС (`Platform.operatingSystem`, `Platform.operatingSystemVersion`).
     - Текущая версия Shellit (`PackageInfo.fromPlatform()`).
     - **Строжайший Zero-Knowledge протокол:** категорически запрещено передавать IP-адреса хостов, ключи, пароли, сниппеты или логи сессий.

# Руководство по выпуску релизов Shellit

В репозитории Shellit настроена автоматическая мультиплатформенная сборка через **GitHub Actions**.

При каждом релизе автоматически компилируются и публикуются следующие файлы:
- **`Shellit-Setup-x64-vX.Y.Z.exe`** — полноценный Windows-инсталлятор с мастером установки, ярлыками в меню «Пуск», на Рабочем столе и корректной деинсталляцией.
- **`Shellit-Windows-x64-vX.Y.Z.zip`** — портативная версия для Windows (распаковал и запустил).
- **`Shellit-Linux-x64-vX.Y.Z.tar.gz`** — готовый архив бинарников для любых Linux-дистрибутивов.
- **`Shellit-Android-vX.Y.Z.apk`** — установочный файл для прямого запуска на смартфонах и планшетах Android.

---

## Способ 1: Выпуск через Git-тег (Быстрый и основной)

1. Убедитесь, что все нужные изменения закоммичены и отправлены в ветку `main`.
2. Если вы меняете мажорную/минорную версию, обновите поле `version:` в [`apps/shellit/pubspec.yaml`](../apps/shellit/pubspec.yaml).
3. Создайте тег с версией и отправьте его на GitHub:
   ```bash
   git tag v0.1.0
   git push origin v0.1.0
   ```
4. Перейдите во вкладку **Actions** в репозитории на GitHub — сборка запустится автоматически.
5. После завершения готовый релиз появится во вкладке **Releases**.

---

## Способ 2: Ручной запуск через браузер (workflow_dispatch)

1. Откройте репозиторий на GitHub: `https://github.com/kobaltgit/Shellit`.
2. Перейдите на вкладку **Actions**.
3. В левой панели выберите воркфлоу **`Release Multiplatform`**.
4. Нажмите кнопку **Run workflow**:
   - Выберите ветку (`main`).
   - При необходимости снимите галочку *Mark as prerelease*, если это стабильный финальный релиз.
5. Нажмите зеленую кнопку **Run workflow**.

---

## Как формируется описание релиза (Release Notes)

Описание релиза генерируется автоматически сервисом GitHub на основе коммитов и Pull Request со времени предыдущего релиза.

Секции автоматически форматируются согласно файлу `.github/release.yml`:
- 🚀 **New Features & Enhancements** (коммиты/PR с тегами `feat`)
- 🐛 **Bug Fixes & Stability** (коммиты/PR с тегами `fix`)
- 🛡️ **Security & Vault** (изменения безопасности и шифрования)
- ⚡ **UI & Terminal Experience** (улучшения интерфейса и терминала)
- 📦 **Dependency Updates & Maintenance** (обновления библиотек)

Вы также всегда можете вручную отредактировать описание любого релиза через кнопку «Edit Release» прямо на GitHub.

# 🚀 Shellit v0.8.7 — Исправление проверки обновлений и актуализация веб-летописи

## 📌 О релизе: Hotfix чекера обновлений и гибкая летопись

В релизе **v0.8.7** устранен критический дефект в механизме проверки обновлений приложения (`BUG-043`) и удалена жесткая привязка к номеру глав в веб-летописи.

---

## 🔒 Ключевые изменения

### 1. Исправление проверки обновлений GitHub Releases (BUG-043)
- **Причина дефекта:** Ранее карточка `AboutSettingsCard` опрашивала эндпоинт GitHub REST API `https://api.github.com/repos/kobaltgit/Shellit/releases/latest`. В соответствии со спецификацией GitHub API этот эндпоинт всегда возвращает `HTTP 404 Not Found`, если все релизы в репозитории помечены как **Pre-release** (что характерно для активной фазы Alpha/Beta разработки). В результате при нажатии на «Проверить обновления» приложение считало, что удаленных релизов нет, и ошибочно сообщало, что установлена последняя версия.
- **Решение:** Эндпоинт переключен на `https://api.github.com/repos/kobaltgit/Shellit/releases?per_page=5`. Клиент корректно парсит список релизов, отсекает черновые сборки (`r['draft'] != true`) и корректно распознает pre-release версии (`v0.8.7`, `v0.8.6` и т.д.), предлагая пользователю диалог обновления с прямыми ссылками на бинарные сборки.
- **Тесты:** Логика покрыта юнит-тестами в `apps/shellit/test/about_settings_card_test.dart` (7/7 успешно).

### 2. Устранение жесткого хардкода глав на сайте
- В интерфейсе веб-сайта (`apps/website/src/pages/ru/chronicle/index.astro`, `apps/website/src/pages/chronicle/index.astro`), RSS-лентах `rss.xml.ts` и `llms.txt` жестко закодированное число глав («8 тематических глав») заменено на динамическую формулировку («Тематические главы...»). Это исключает необходимость ручного инкремента числа при публикации новых актов.

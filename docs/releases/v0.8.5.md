# 🛡️ Shellit v0.8.5 — Комплексный аудит безопасности и устранение уязвимостей (Security Hardening Release)

## 📌 О релизе: Открытость, честность и прозрачность

В релизе v0.8.4 была заложена основа TOFU и защиты от MitM. Однако в ходе глубокого независимого анализа безопасности (с привлечением LLM-моделей разной архитектуры и моделирования атак) в первоначальной реализации был выявлен ряд критических уязвимостей и архитектурных дефектов:
1. **Тихий обход проверки ключа хоста (Silent Bypass / Fail-Open)**: при отсутствии UI-коллбэка верификации соединение молча разрешалось (`return true`).
2. **Аварийный сбой при проверке отпечатка (`FormatException` crash)**: попытка декодировать бинарный 32-байтный дайджест SHA-256 через `utf8.decode()`.
3. **Обход TOFU при отсутствии UI-контекста**: в фоновых подключениях неизвестный хост принимался как доверенный.
4. **Остаточные секреты в куче оперативной памяти Dart**: использование неизменяемых строк `String` для паролей и ключей препятствовало занулению памяти сборщиком мусора Dart.
5. **Недостаточная валидация в Desktop Plugin SDK**: отсутствие строгой схемы JSON-RPC 2.0, белого списка методов и защиты от Path Traversal и null-byte инъекций.
6. **Завышенные маркетинговые заявления**: несоответствие статуса «Production-Ready Zero-Trust Fortress» реальной стадии альфа-разработки.

В релизе **v0.8.5** все выявленные уязвимости полностью устранены, кодовая база покрыта строгими регрессионными тестами, ссылки и версии на сайте полностью автоматизированы, а статус проекта честно скорректирован.

## 🔒 Подробное описание проведенных исправлений

### 1. Критическое исправление SSH TOFU & MitM: переход на строгий Fail-Closed (BUG-035)
* **Устранение Fail-Open:** В `packages/ssh_network_core/lib/src/session/ssh_client_service.dart` полностью ликвидирован возврат `true` при отсутствии коллбэка. Если `onVerifyHostKey == null` или если коллбэк завершается ошибкой/исключением, соединение **безусловно прерывается (`return false`)** с записью алерта безопасности и исключением `SSHHostkeyError`.
* **Устранение краша `utf8.decode`:** Сырой 32-байтный бинарный дайджест SHA-256 из `dartssh2` теперь форматируется по каноническому стандарту OpenSSH: `SHA256:${base64.encode(fingerprint).replaceAll('=', '')}`. Код протестирован на байтах с невалидным UTF-8 (`0xFF`, `0xFE`, `0x80`), исключая любые сбои парсинга.
* **Поддержка каноничных форматов в Randomart:** Алгоритм Drunken Bishop (`Randomart.fromString` и `fromBytes`) адаптирован под каноничный формат OpenSSH `SHA256:<base64>`.
* **Защита в UI-контроллере:** В `SessionConnectController` (`apps/shellit`) устранена брешь `return !hasMismatch` при отсутствии контекста UI — теперь для любых неизвестных или недоверенных хостов возвращается `false`.

### 2. Гигиена оперативной памяти в Dart (Zeroization) (BUG-036)
* **Отказ от неизменяемых строк:** В `packages/storage_vault` все чувствительные операции (деривация мастер-ключа, расшифровка приватных ключей и паролей) переведены на изменяемые байтовые буферы `Uint8List`.
* **Принудительное зануление памяти:** Внедрены методы `deriveMasterKeyFromBytes`, `withDecryptedBytes` и `withMasterKeyBytes`, где в блоках `finally` память буферов принудительно перезаписывается нулями (`.fillRange(0, length, 0)`), даже при возникновении исключений.
* **Уничтожение мастер-ключа:** При закрытии приложения или блокировке хранилища у объектов `SecretKey` вызывается метод `.destroy()`, предотвращая сохранение ключевого материала в дампе оперативной памяти.
* **Канонизация в БД:** Репозиторий `KnownHostRepository` сохраняет и выполняет поиск отпечатков хостов исключительно в каноничном формате `SHA256:<base64-without-padding>`.

### 3. Защита песочницы Desktop Plugin SDK (BUG-036)
* **Строгая валидация JSON-RPC 2.0:** Все входящие сообщения от плагинов проверяются по строгой схеме протокола (`jsonrpc: "2.0"`, целостность `id`, наличие `method`).
* **Белый список методов (Method Whitelisting):** Вызовы неразрешенных методов немедленно отклоняются с ошибкой JSON-RPC `-32601 (Method not found)`.
* **Защита от Path Traversal и инъекций:** При операциях с изолированным хранилищем плагинов (`storage.get`, `storage.set`) ключи проверяются на отсутствие null-байтов (`\x00`) и попыток выхода из директории (`..`, `/`, `\`). Недопустимые ключи отклоняются с ошибкой `-32602 (Invalid params)`.
* **Универсальные CSP-заголовки:** Внутренний HTTP-сервер отдает строгие заголовки `Content-Security-Policy`, `X-Content-Type-Options: nosniff` и `X-Frame-Options: DENY` на любые ответы (включая ошибки 404 и 500).

### 4. Честное позиционирование и прозрачность (Transparency)
* **Статус Alpha / Developer Preview (Experimental):** В `README.md`, `README.ru.md` и на официальном сайте скорректировано позиционирование проекта. Заявления о «промышленной неуязвимости» заменены на открытое признание активной стадии альфа-разработки с экспериментальной Zero-Trust архитектурой.
* **Приглашение к аудиту:** Добавлен раздел «Security Status & Transparency» с открытым призывом к ИБ-исследователям и криптографам изучать кодовую базу и ответственно сообщать о находках через GitHub Security Advisories.
* **Строгий CI/CD анализ:** В GitHub Actions CI создан воркфлоу с шагом `dart analyze --fatal-infos`, предотвращающий коммит потенциально опасных конструкций и предупреждений компилятора.

### 5. Полная автоматизация версий и ссылок на сайте
* **Единый источник правды:** Версия на сайте (`apps/website`) и ссылки на скачивание артефактов (.exe, .zip, .tar.gz, .apk) теперь полностью формируются автоматически из `apps/shellit/pubspec.yaml` и GitHub Releases API без необходимости ручного редактирования файлов при каждом релизе.

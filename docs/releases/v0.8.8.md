# 🚀 Shellit v0.8.8 — Спасение пула сокетов и стабильность фоновой телеметрии (Socket Pool Salvation)

## 📌 О релизе / Release Overview

В релизе **v0.8.8** полностью ликвидирован критический дефект исчерпания сетевого пула операционной системы (`BUG-044`), возникавший из-за полузакрытых TCP-сокетов при фоновом замере RTT-задержки серверов. 

Release **v0.8.8** resolves a critical OS network pool exhaustion issue (`BUG-044`) caused by half-closed TCP sockets during background host RTT latency measurements.

---

## 🔒 Ключевые изменения / Key Changes

### 1. Ликвидация утечки сокетов в `pingHost` (`BUG-044`)
- **Проблема:** Метод замера пинга вызывал `await socket.close()`. В сетевой модели Dart (`dart:io`) метод `close()` закрывает поток только на запись (`shutdown(SHUT_WR)`), отправляя TCP FIN, но оставляя сокет открытым на чтение. Так как OpenSSH-серверы при рукопожатии сразу отправляют идентификационный баннер (`SSH-2.0-OpenSSH...`), сокет зависал с непрочитанными данными в буфере ядра. Дескрипторы сокетов и динамические порты Windows удерживались операционной системой, что приводило к монотонной утечке портов вплоть до полного исчерпания пула эфемеров (все 16 384 порта в диапазоне 49152–65535) и сетевого блэкаута (`WSAENOBUFS`).
- **Решение:** В сервисе `SshClientService.pingHost` закрытие сокета обернуто в блок `finally { socket?.destroy(); }`. Метод `socket.destroy()` гарантированно разрывает двусторонний сетевой канал на уровне ядра ОС и немедленно освобождает системный порт.
- **Отказоустойчивость сессий:** В методы `createTerminalSession` и `openSftpSession` добавлен отказоустойчивый блок `finally`, гарантирующий вызов `client?.close()` и `socket?.destroy()` при любых сбоях аутентификации или отклонении хост-ключа.

### 2. Оптимизация реактивного слоя телеметрии в SQLite
- **Проблема:** Каждые 15 секунд фоновый таймер телеметрии записывал RTT-задержку каждого хоста в базу данных Drift (`hostsTable`), вызывая лавину событий в реактивном потоке `watchAllHosts()` и бесконечные перерисовки UI-компонентов.
- **Решение:** В метод `HostsNotifier.updateHostLatency` добавлен флаг `persist: false`. Пинг теперь обновляется в оперативной памяти виджетов мгновенно без дисковых операций ввода-вывода и без реактивного шума.

### 3. Веб-летопись: Акт X
- На официальном портале `shellit.top` опубликована новая глава хроники: **Акт X: Спасение пула сокетов** (на русском и английском языках) с интерактивным разбором бага, стенограммой реального инцидента и сравнительным анализом кода (`CodeDiffViewer`).
